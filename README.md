# HTTP/1.1 Calculator on the Line

A raw TCP socket-based HTTP/1.1 calculator server built from scratch in Python with zero external libraries or web frameworks.

---

## 1. Problem Overview & Core Challenge

In early HTTP/1.0, servers handled request delimitation simply by closing the connection (`EOF`) after transmitting the response. While simple, this required a new TCP handshake (3-way handshake) and teardown for every single request, introducing significant latency overhead.

In **HTTP/1.1 persistent connections (`Keep-Alive`)**, the underlying TCP connection remains open across multiple consecutive requests. This introduces the central networking challenge:

> **Where does one request end and the next begin on a continuous byte stream?**

Since TCP is a stream-oriented protocol without inherent message boundaries, a single `recv()` call can yield a partial request, an exact request, or multiple requests queued back-to-back (HTTP pipelining). Byte $N+1$ belongs to the next request and cannot be discarded or over-consumed.

---

## 2. Architecture & Design Decisions

### A. Stream Buffering & Frame Boundary Parsing
- **Byte Buffer per Connection**: We maintain a persistent `bytearray` buffer for each active socket session.
- **Header Delimitation**: The server accumulates data from `recv()` until the boundary marker `\r\n\r\n` is detected.
- **Exact Body Slicing**: After parsing the `Content-Length` header (if present), the server reads exactly that many body bytes from the buffer, slicing them out while keeping any surplus bytes in the buffer for subsequent requests. This natively supports **HTTP pipelining**.

### B. HTTP/1.1 Protocol Compliance
- **Mandatory `Host` Header**: Per RFC 7230 / HTTP/1.1 specification, any request lacking a `Host` header is rejected immediately with `400 Bad Request`.
- **Accurate `Content-Length`**: Every response generated by the server calculates and includes the exact byte length of the body so the client knows precisely when the response has finished downloading.

### C. Connection Lifecycle & Idle Defense
- **Persistent Connections**: By default, connections remain open to service future requests.
- **`Connection: close` Support**: If the client specifies `Connection: close` in its headers, the server responds with `Connection: close` and gracefully closes the socket after transmitting the response.
- **Idle Timeout**: To defend against orphaned or hanging client connections, each socket is configured with a 5.0-second timeout (`settimeout(5.0)`). If an idle socket times out between requests, the connection is cleanly closed to free up system resources.

## 3. Supported Endpoints & Status Codes

| Method | Endpoint & Query | Response Code | Description |
| :--- | :--- | :--- | :--- |
| `GET` | `/add?a=2&b=3` | `200 OK` (Body: `5`) | Computes $a + b$ |
| `GET` | `/sub?a=10&b=4` | `200 OK` (Body: `6`) | Computes $a - b$ |
| `GET` | `/mul?a=6&b=7` | `200 OK` (Body: `42`) | Computes $a \times b$ |
| `GET` | `/div?a=9&b=3` | `200 OK` (Body: `3`) | Computes $a / b$ |
| `GET` | `/div?a=1&b=0` | `400 Bad Request` | Division by zero error |
| `GET` | `/add?a=x&b=3` | `400 Bad Request` | Non-numeric parameter validation |
| `GET` | `/add` *(no Host)* | `400 Bad Request` | Missing mandatory HTTP/1.1 Host header |
| `GET` | `/pow?a=2&b=8` | `404 Not Found` | Unknown / unsupported endpoint |
| `POST` | `/add` | `405 Method Not Allowed` | Disallowed HTTP method on calculator route |

## 5. How to Run & Test

### Step 1: Start the Server
```bash
python3 server.py 8080
```

### Step 2: Run the Test Client
In a separate terminal window:
```bash
python3 test_client.py 8080
```

### Test Output Verification:
The test suite performs:
1. **Official Grading Test**: Establishes **one single socket connection** (`socket.create_connection`), fires 6 consecutive requests across that connection, validates all responses, and asserts `socket still open: True`.
2. **Extended Edge Case Suite**: Tests whole number formatting (`/div?a=9&b=3` $\rightarrow$ `200 3`), missing `Host` headers, non-numeric parameters, **HTTP pipelining** (batch transmission), and `Connection: close` teardown.
